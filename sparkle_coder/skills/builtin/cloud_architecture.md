# Cloud Architecture Mastery
Choose managed services and topology from reliability, data, security and cost requirements—not trend. Define network/trust boundaries, persistent state, scaling unit, region strategy, backups and operational ownership.

Prefer stateless compute plus explicit durable stores when it simplifies recovery. Keep infrastructure configuration reproducible and separate from application secrets. Design for provider/service limits and failure domains.

Master standard: architecture has a clear failure model, data durability story, cost/scaling model and deploy/rollback path.
