# Python Mastery
Write idiomatic, explicit Python that matches the project's supported version and existing style. Prefer small functions, clear data flow, context managers, pathlib, standard-library solutions where appropriate, precise exceptions, and type hints where they improve interfaces.

Do not introduce frameworks, metaprogramming, async code or abstraction layers unless the problem needs them. Preserve tracebacks and error context; avoid bare excepts and silent failure. Keep imports and dependency changes minimal.

Master standard: code is readable without cleverness, edge cases are deliberate, resource/error handling is correct, and focused tests exercise the public behavior.
