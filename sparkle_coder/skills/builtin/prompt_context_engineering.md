# Prompt & Context Engineering Mastery
Treat context as scarce, ordered program input. Put durable behavioral contracts in the system layer, task-specific instructions near the task, and retrieved evidence only when relevant. Remove duplicated instructions, stale history and giant tool outputs.

Use structured delimiters and explicit precedence for untrusted/user/retrieved text. Do not rely on vague roleplay such as “be an expert” without concrete acceptance standards. Prefer concise high-signal examples over long generic prose.

Master standard: each context block has a reason to exist, prompt growth is bounded, conflicting instructions resolve predictably, and important rules survive long-running sessions.
