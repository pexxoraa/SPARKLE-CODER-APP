# Refactoring Mastery
Refactor to reduce cognitive load while preserving behavior. First identify the duplication, mixed responsibility, unstable interface or hidden coupling that makes change risky. Make small structural moves with tests staying green.

Do not combine broad redesign with an unrelated feature or bug fix unless necessary. Prefer clearer names, narrower functions, explicit interfaces and one source of truth over abstraction for its own sake.

Master standard: the resulting code has fewer reasons to change, fewer hidden dependencies, and equal or better testability without unnecessary layers.
